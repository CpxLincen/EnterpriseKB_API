# 文档解析与入库技术说明

> 记录时间：2026-09-15
> 状态：本文档系统梳理「文档解析 → 切块 → 向量化入库」这一链路的设计、已实现能力、
> 遗留问题与解决方案、以及后续路线图，作为工程化迭代的基准。实现以
> `app/services/ingestion.py` 为准。

---

## 一、定位与总览

文档解析入库是 RAG 系统的「上限」：解析质量决定检索与回答质量。本链路的目标是
把多种格式的企业制度文档，尽可能**结构化、无损、可追溯**地转成文本块并向量化，
同时满足工程化约束（向后兼容、可观测、可测试、可部署、可维护）。

```text
上传（白名单 + 大小限制 + 流式写盘）
  → SHA-256 去重 → 多格式解析（正文 + 表格结构化）
  → 切块（正文按标点 / 表格按完整行） → 批量 Embedding → 写入 pgvector
```

## 二、当前已实现能力

| 格式 | 解析方式 | 表格 | 合并单元格 |
|---|---|---|---|
| `.md` / `.txt` | UTF-8 优先，降级 GB18030 | - | - |
| `.docx` | XML 树按文档顺序识别段落 + `<w:tbl>` | ✅ 转 Markdown | ✅ `gridSpan` + `vMerge` |
| `.xlsx` | openpyxl 逐 sheet | ✅ 整 sheet 转 Markdown | ✅ `merged_cells` 回填 |
| `.pptx` | python-pptx 逐页标题/正文/表格/备注/图表/SmartArt | ✅ 转 Markdown | ✅ `gridSpan` / `rowSpan` |
| `.html` / `.epub` | 标准库 HTMLParser，EPUB 按 OPF spine | ✅ `<table>` 转 Markdown | ✅ `rowspan` / `colspan` |
| `.pdf` | PyMuPDF：正文 + 表格，降级 pypdf | ✅ 有边框（lines）+ 无边框（词坐标） | ✅ `None` 延续位回填 |

配套能力：
- **块类型**：`document_chunks.content_type`（`text` / `table`），旧库幂等 `ALTER TABLE` 补齐；
- **表格切块**：`chunk_table_text()` 按完整行切分，不拆散行列；
- **扫描 PDF OCR**：可选能力（PyMuPDF 渲染 + `rapidocr-onnxruntime`，延迟导入、装即用）；
- **混合 PDF 提示**：部分扫描页经 `warnings` 返回（CLI 打印 / 前端展示），不再静默跳过；
- **审计指标**：上传事件记录 `chunks` 数（`extra` 字段可扩展）。

## 三、关键设计

### 3.1 统一解析结果 `ParsedBlock`

所有 `read_*` 返回 `list[ParsedBlock(text, page_number, content_type)]`，供
`_split_blocks()` 按 `content_type` 分派切块（正文走 `chunk_text`，表格走
`chunk_table_text`），再统一写入 `DocumentChunk`。

### 3.2 表格转 Markdown

`_table_to_markdown()`：第一行视为表头，处理不等长行（补空）、过滤全空行，
输出 `| A | B |` + `|---|---|`；可选 caption（xlsx 的 sheet 名）。

### 3.3 PDF 表格检测（两路）

1. **有边框表格**：`find_tables()` 默认 `lines` 策略，`table.extract()` 直接取文本；
2. **无边框表格**（自研，`_detect_borderless_tables()`）：
   - `get_text("words")` 取词坐标 → 按 y 聚类成行 → 按「相对水平间隙」切单元格
     （用行内间隙中位数做阈值，区分列间空隙与单元格内空格）→ 连续多列行分组 →
     跨行列锚点聚类 → 按锚点填充（允许空单元格）；
   - **门槛：≥2 列**；2 列候选对左侧列做「编号/项目符号」负向过滤，并对长单元格
     （正文/定义列表形态）做长度过滤，避免把编号列表 / 双栏正文误判为表格；
   - 检测到的表格区域会从正文文本块中剔除，避免重复入库。

> PyMuPDF 首次 `find_tables()` 会向 stdout 打印一条 pymupdf_layout 提示，已由
> `_find_tables()` 在进程首次调用时吞掉，避免污染审计日志 JSON 行。

### 3.4 合并单元格处理

- **DOCX**：解析 `<w:gridSpan>`（水平跨列，复制展开）与 `<w:vMerge>`
  （垂直合并，`restart` 值向下填充到 `continue`），展平成规则二维表；
- **XLSX**：改用非 read_only 模式（read_only 无 `merged_cells`），
  对每个合并区域把左上角值回填到区域内所有单元格；
- **PDF**：✅ `extract()` 对合并格返回 `None`（真空格返回 `""`），据此先横向后纵向
  把 `None` 还原为合并主格值、不动真空格；
- **PPTX / HTML**：✅ PPTX 用 DrawingML `gridSpan`/`rowSpan`、HTML 用 `rowspan`/`colspan` 展平。

## 四、遗留问题与解决方案

### 4.1 正确性（功能缺口）

| # | 问题 | 根因 | 解决方案 |
|---|---|---|---|
| 1 | 2 列无边框表格不检测 | 为防「编号列表/标题」误报，门槛设为 ≥3 列 | ✅ 已解决（2026-09-19）：≥2 列 + 编号/项目符号负向过滤 + 长单元格长度过滤 |
| 2 | PPTX / HTML 合并单元格未处理 | ✅ 已解决（2026-09-17） | PPTX 用 DrawingML `gridSpan/rowSpan`；HTML 用 `rowspan/colspan` 展平 |
| 3 | PDF 合并单元格无法可靠还原 | `extract()` 返回空，信息丢失 | ✅ 已解决（2026-09-19）：`None` 延续位先横后纵回填主格值，真空格不动 |
| 4 | PDF 跨页表格被切开、续页丢表头 | `find_tables()` 逐页检测 | ✅ 已解决（2026-09-19）：连续页同列数 + 贴页底/顶 + 首行不同 → 合并并补表头 |
| 5 | 多栏 PDF 版面乱序 | `(y0, x0)` 排序对多栏失效 | ✅ 已解决（2026-09-19）：自研 x 空隙分栏 + 通栏块插入的阅读顺序排序 |
| 6 | 图片/图表完全丢失（第三层未做） | 只提取文本与表格 | 路线 A：OCR + VLM 生成描述入库；路线 B：CLIP 视觉向量多路检索 |
| 7 | 各格式细节缺口 | 未提取 | ✅ 已解决（2026-09-19）：PPTX 备注/图表/SmartArt、XLSX 公式回退 + sheet 多表、DOCX 页眉页脚/文本框、HTML/EPUB 图片 alt |
| 8 | OCR 未落地 + 后处理缺失 | `rapidocr` 未装；按检测框拼接会乱序 | 装 rapidocr 并验证兼容；按检测框坐标排序还原阅读顺序 |
